Chuẩn bị trước khi bấm Deploy

  • npm run build chạy qua ở máy, không còn lỗi TypeScript.
  • .env không nằm trong git; chỉ có .env.example.
  • Schema có migration, không chỉ db push.
  • Seed là dữ liệu mô phỏng, không có tên/email khách thật.
  • Có /api/health để kiểm tra app và database.
  • Có mật khẩu chung hoặc allowlist trước khi gửi link ra ngoài.

Đưa code lên GitHub

git init git add . git commit -m "crm demo" git branch -M main git remote add origin git@github.com:... git push -u origin main

Kiểm tra

  • .env không có trong repo.
  • node_modules không có trong repo.
  • README ghi cách chạy và cách deploy.
  • Repo private nếu chưa muốn công khai.
Đừng commit connection string, API key, mật khẩu. Nếu lỡ commit, đổi mật khẩu ngay; xoá file khỏi git không đủ.

Tạo Postgres trên Neon

Ba bước

  • Tạo project, chọn region gần Việt Nam.
  • Lấy connection string có sslmode=require.
  • Dùng pooled connection cho serverless.
# .env production DATABASE_URL="postgresql://user:pass@ ep-xxx-pooler.ap-southeast-1.aws.neon.tech/ crm?sslmode=require"

Database là thứ duy nhất phải sống lâu hơn máy bạn. Chọn nơi có backup và biết cách khôi phục.

Migration và seed trên database production

# trỏ tạm DATABASE_URL vào DB production npx prisma migrate deploy npm run db:seed # kiểm tra curl https://your-app.vercel.app/api/health # {"ok":true,"db":"up","counts":{...}}
Seed một lần. Chạy lại seed sẽ xoá dữ liệu người dùng đã nhập. Trước khi seed lại, backup hoặc dùng nhánh database.

Migration là thay đổi cấu trúc, seed là dữ liệu mẫu. Đừng trộn hai việc vào một lệnh.

Deploy lần đầu: nhìn gì trên màn hình

Build log

  • Có chạy prisma generate không.
  • Có lỗi TypeScript không.
  • Có thiếu biến môi trường không.
  • Build xong trong bao lâu.

Mở link

  • Trang đầu có dữ liệu, không trắng.
  • Đăng nhập/mật khẩu hoạt động.
  • Bấm một lead, một deal.
  • Mở bằng điện thoại.

Deploy thành công chưa có nghĩa app đúng. Phải bấm thử luồng thật.

Smoke test sau deploy: 7 bước

  • Mở link bằng điện thoại, thấy dashboard.
  • Tạo lead mới; lead xuất hiện trong danh sách.
  • Giao lead; trạng thái đổi, audit có dòng mới.
  • Chuyển lead thành deal; deal mở đúng khách hàng.
  • Ghi hoạt động; tương tác cuối đổi, cờ nguội biến mất.
  • Chuyển giai đoạn; xác suất và giá trị kỳ vọng đổi.
  • Mở báo cáo, xuất CSV, gọi /api/health.

In checklist này ra giấy. Nhóm khác dùng thử và ghi lỗi, không chỉ người build tự kiểm.

Bảo vệ bản demo trước khi gửi link

Mật khẩu

Basic Auth hoặc mật khẩu chung. Không để URL công khai cho cả công ty.

Dữ liệu

Chỉ dữ liệu hư cấu. Banner “Dữ liệu mô phỏng” trên mọi trang.

Index

robots.txt chặn tìm kiếm. Không xuất hiện trên Google.

Đừng đưa dữ liệu khách thật lên bản demo. Nếu cần dùng thật, phải có phê duyệt dữ liệu, phân quyền thật và log truy cập.

Một link demo bị lộ không nguy hiểm bằng một link demo có dữ liệu thật bị lộ.

Cho app tự chạy lúc 7:00

// vercel.json { "crons": [{ "path": "/api/cron/digest", "schedule": "0 0 * * *" }] }

00:00 UTC = 07:00 giờ Việt Nam.

API cron làm gì

  • Kiểm tra CRON_SECRET.
  • Tổng hợp deal quá hạn, deal nguội, lead trễ SLA.
  • Trả JSON hoặc gửi email/Slack.
  • Ghi log lần chạy để biết có chạy thật không.

Cron không tự sửa việc. Nó chỉ nhắc đúng người, đúng việc, trước khi quá muộn.

Kiểm cron bằng tay trước khi tin

curl -H "Authorization: Bearer $CRON_SECRET" \ https://your-app.vercel.app/api/cron/digest # {"totals":{"overdue":23,"stale":6,"lateLeads":6}, ...}

Nếu 401

Secret trên Vercel khác secret đang gọi. Kiểm tra lại biến môi trường.

Nếu 500

Database hoặc query lỗi. Mở Vercel Functions log, xem stack trace.

Đừng đợi 7:00 sáng mai mới biết cron hỏng.

Khi bản mới hỏng: rollback

Vercel

  • Deployments → chọn bản trước.
  • Bấm Promote to Production.
  • Link cũ trở lại bản chạy được trong vài giây.

Database

  • Không rollback database bằng nút.
  • Dùng nhánh/branch của Neon hoặc backup.
  • Migration xoá cột là việc nguy hiểm; phải có kế hoạch.

Code rollback dễ. Dữ liệu rollback khó. Vì vậy migration phải nhỏ và có backup trước.

Bài tập cuối buổi

  • Deploy lát cắt của nhóm lên Vercel + Neon.
  • Gửi link cho nhóm bên cạnh dùng thử trong 5 phút.

  • Sửa lỗi nặng nhất, deploy lại.
  • Ghi lại link, tài khoản demo và việc tiếp theo.
